## Initial repository setup
Student A: Create an EMPTY GitHub repository (do not initialize with a README, .gitignore, or license), clone it locally, copy all six starter files into that local clone, commit, push, then invite Student B. Ensure the hidden `.gitignore` file is included. Student B: Clone the same team repository to a separate local computer.

Configure Git author name/email and confirm the email is linked to your GitHub account (or use your GitHub noreply email). For authenticated HTTPS pushes, use Git Credential Manager or a supported token-based sign-in rather than a GitHub account password.

If your repository or GitHub Project board is private, grant the instructor access separately to both. The instructor's GitHub username will be provided in class.

## Working agreement
- Both students work locally in separate clones.
- Do not commit directly to `main` after setup.
- Create a feature branch for each issue; open a PR and request peer review.
- Do not merge your own PR before partner review.
- Use GitHub Projects and Issues to plan and track work. Link an Issue through `Closes #N` in the PR description.
- Do any `git revert` demonstration on a separate branch, and merge through a reviewed PR.
